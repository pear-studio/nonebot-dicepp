# v3.0.0rc15

- 镜像: ghcr.io/pear-studio/nonebot-dicepp:v3.0.0rc15
- Windows: `DicePP-v3.0.0rc15-win64-Portable.zip`、独立 `DicePP-v3.0.0rc15-win64-Setup.exe` 和 Velopack feed
- 数据变更: no
- 配置变更: yes
- 变更范围: runtime, manager, deployment, config, documentation
- 自动升级: no
- 最低 Manager 版本: 1.0

## Changed

- OneBot WebSocket 默认只监听 127.0.0.1，同机部署不再触发 Windows 防火墙入站提示。Docker 部署行为不变（compose 显式设置 `DICEPP_ONEBOT_HOST=0.0.0.0`）；源码或桌面运行且需要从远程接入 OneBot 客户端时，显式设置 `DICEPP_ONEBOT_HOST=0.0.0.0`。
- Windows 升级提交成功后自动清理旧版本 UpdateGuard 缓存，`%LOCALAPPDATA%\DicePP-UpdateGuard` 不再随升级版本数无限累积。

## Fixed

- Windows 升级事务中 UpdateGuard 在安装根目录内被 Velopack 终止、并随 Manager 退出被一并杀死，导致升级无法提交、目标启动失败后也无法自动回退；现 Guard 复制到用户缓存目录后外置启动，升级提交与失败回退恢复正常。
- 网络不佳时升级包下载截断失败后反复从头下载、大文件基本无法完成；现支持 `.part` 断点续传与有界重试，HTTP 错误（404/403 等）快速失败不再无效重试。
- 未绑定 Bot 的实例在升级或回退后被控制通道心跳检查误判为不健康；现在无绑定 Bot 时跳过该检查。

## Risk Notes

- Windows 已部署 rc13/rc14 的实例，其 Manager 不包含 UpdateGuard 外置修复，不能依靠自动升级获得本版本（升级仍会在 Guard 交接阶段失败）。请下载本版本 Portable 或 Setup 手工迁移；迁移后后续版本的自动升级链路恢复正常。
- Linux Compose 的 bot 服务新增环境变量 `DICEPP_ONEBOT_HOST=0.0.0.0`，升级必须使用本版本附带的 docker-compose.yml 重建容器，不能仅切换镜像 tag。
- 仍在运行 v3.0.0rc11/rc12 的实例升级链路在出厂代码中已损坏，请先按 v3.0.0rc13 Risk Notes 手工迁移。
- 非 Docker 部署且 OneBot 客户端运行在其他机器上的用户，升级后需设置 `DICEPP_ONEBOT_HOST=0.0.0.0` 才能继续接入。
