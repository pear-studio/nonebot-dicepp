# v3.0.0rc6

- 镜像: ghcr.io/pear-studio/nonebot-dicepp:v3.0.0rc6
- Windows: DicePP-v3.0.0rc6-win64.zip
- 数据变更: yes
- 配置变更: yes

## Added
- Dashboard 新增存档系统，支持创建、校验和恢复 bot 完整存档（zip + manifest，含 checksum/版本/时间戳），可按 data/config/bots 三种 scope 恢复。
- Dashboard 新增 Manager 服务与运行监控，支持管理 bot 生命周期（启动/停止/重启），提供 Process 和 Docker Compose 两种 runtime backend。
- Dashboard 新增运行时日志模块，支持日志轮转与实时查看。
- Dashboard 角色卡模块新增结构化编辑，卡片网格替代表格展示，支持基本信息/对话/世界书/扩展四个区域分区编辑，default 角色卡只读保护。
- Dashboard 配置编辑新增类型感知内联控件（boolean 开关、integer/number 约束输入、enum 下拉、List[str] 标签编辑器），JSON 视图拆分为 user.json / Bot 配置两个子标签页。
- 新增 Windows 单入口打包与系统托盘运行（DicePP.exe 启动器 + DicePP-Runtime.exe bot），安装包随带用户文档。
- 新增 Story Deck 叙事条目系统，SA 从自由文本重构为结构化 Front/Thread 规划，DM 可自动匹配注入共享叙事条目。
- 新增 Conversation 变更通知订阅系统，角色状态变化（体力/心情/健康）通过通知管道 diff 注入，替代原先每轮 prompt 内联拼接。
- 新增 ChatOrchestrator 与 ConversationStore，SQLite 持久化会话消息，集成 LLM 调用协调与门控（睡眠/信誉/去重）。
- 新增 Schema Lifecycle 系统，声明式 SchemaTarget 配合事务性 forward migration，persona 数据库纳入统一 lifecycle 管理。
- 新增 Clock 抽象（WallClock/SteppedClock），为 warp 时间加速功能奠基。
- 新增 JRRP transient_message 旁路，后即焚的消息不再写入 message_stream 污染上下文。
- 新增 tick 槽位生命周期诊断日志，方便排查角色生活模拟行为。

## Changed
- 角色卡选择从全局配置迁移至 Bot 级：`PersonaConfig.character_name`（global.json）删除，改为 `BotConfig.persona`。persona 为空时自动禁用 Persona 模块。
- DM-Character 交互协议重写为 want_to_end + end_conversation 共识终止，DM 从"行动裁决者"转为"世界叙述者"，只呈现情境不替角色做决定。
- DM 链循环翻转为角色主导：角色提出企图 → DM 评估 DC → 叙事结果 → 角色反应，单次 AgentRuntime.run() 内完成。
- 场景文本（scenario）不再注入日常 prompt，仅在 Life 首次启动时注入 DM context。
- Agent 纠正机制拆分为 max_output_corrections（输出协议纠正）和 max_tool_corrections（工具执行错误重试），background_llm_max_rounds 默认值从 1 调整为 10。
- Config loader 重构：JSON 配置文件规范化重写（丢弃未知字段、填充默认值），敏感字段保护防误删。
- 日志模块重构：stderr 自适应彩色输出、Loguru 格式符全部迁移为 `{}`、运行时 `%`-格式化检测告警。
- 用户昵称 fallback 链扩展至 5 级：群特定名 → 全局自定义名 → 群名片 → QQ 昵称 → user_id。
- 角色 reaction 字段字符上限从 80 扩大到 200。
- Persona 日报段 2 标题改为文本格式，统计类简化。
- transient 消息 display_name 从 nickname 改为"系统"，消除群聊格式中用户名视觉重复。

## Fixed
- 修复 Story Deck 全部 5 个工具因 ToolExecutor 签名不匹配导致不可用的问题。
- 修复 edit_fronts 工具因 LLM 传入 dict 导致 .strip() 崩溃。
- 修复 daily_event 写入数据库时使用错误的 delta 值。
- 修复 warp 模拟中跳过槽位被误计入已处理的问题。
- 修复 Character reaction prompt 为建议式无法有效约束角色输出的问题。
- 修复 Docker 中 PersonaCommand 导入报 ModuleNotFoundError。
- 修复 Conversation 统一后 LLM 异常状态检查缺失导致错误信息精度退化。
- 修复命令行双引号短语产生重复 token。
- 修复 LLM provider probe 对永久错误（如 MiniMax 2056/1008/1004）进行无意义重试的问题。
- 修复 Conversation fetch/apply 非事务性导致 LLM 调用失败后状态可能损坏的问题。

## Deprecated
- `PersonaConfig.character_name`（global.json）删除，需迁移至 `BotConfig.persona`（Bot 级配置）。
- 旧 migration 链（v1-v4）及旧 migration 框架删除，替换为 Schema Lifecycle 系统。
- `persona_dm_state` 表删除，替换为 `persona_story_deck` 表。
- `ChatSession` 替换为 `ChatOrchestrator` + `ConversationStore`。
- `EventGenerationAgent` 拆分为 Agent 基类 + DMAgent + CharacterAgent + SAAgent。
- 统计细分维度 `msg_group` / `msg_private` 移除。
- `chain_force_extend_once_prob` 逻辑移除。

## Risk Notes
- 这是发版链路验证用 RC，不作为正式生产版本部署。
- **数据库不兼容**：迁移系统从旧 v1-v4 链替换为 Schema Lifecycle。从 rc5 升级时，现有 `data/` 下的数据库（bot_data.db、log.db、persona_*.db）**无法自动打开**，会在启动时抛出 `UnmanagedDatabaseError`。升级前需备份全部 `data/` 目录。
- Persona 数据库多个表结构变更：`persona_llm_traces.session_id` 重命名为 `interaction_id`，新增 `usage_status`/`usage_raw_json`/`usage_note` 列；`persona_session` 新增 `cursors_json`；`persona_dm_state` 表删除，新增 `persona_sa_state`、`persona_story_deck` 表。`_migrate_schema_t6()` 方法处理部分 persona DB 的前向迁移，但核心数据库迁移需手工处理。
- 新增 `data/dicepp.db` 实例级数据库文件。
- 新增 **9 个环境变量**用于 Manager runtime 配置：`DICEPP_MANAGER_RUNTIME`、`DICEPP_MANAGER_PROCESS_COMMAND`、`DICEPP_MANAGER_PROCESS_CWD`、`DICEPP_MANAGER_PROCESS_STOP_TIMEOUT`、`DICEPP_MANAGER_DOCKER_COMMAND`、`DICEPP_MANAGER_DOCKER_SERVICE`、`DICEPP_MANAGER_DOCKER_CWD`、`DICEPP_MANAGER_DOCKER_TIMEOUT`、`DICEPP_RUNTIME_LOG`。如不使用 Manager 功能可不配置。
- `config/user.json.example` 已从仓库移除，部署时不再需要该模板文件。
- Windows 包新增依赖 `pystray>=0.19` 和 `pillow>=10.0`。
