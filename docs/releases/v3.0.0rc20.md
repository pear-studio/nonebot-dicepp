# v3.0.0rc20

- 数据变更: no
- 配置变更: yes
- 变更范围: runtime, dashboard, manager, config, deployment
- 自动升级: no
- 最低 Manager 版本: 1.0

## Changed

- Dashboard 保存 Bot 配置后会提示受影响的账号，由用户手动重启对应 RuntimeUnit 使配置完整生效；通用 `.reload` 热重载已经停用。
- 资料查询命令收缩为只读，不再通过查询流程写入资料数据。
- 停用已经过时的 DiceHub 命令入口。
- 发布渠道收缩为 GitHub Release 与 GHCR，不再同步 Gitee 镜像。
- 开发、测试、Windows 打包和 Linux 镜像统一以 Python 3.13 为运行基线；源码安装不再支持 Python 3.10–3.12，官方发行包仍然内置解释器。
- Windows 升级删除独立 UpdateGuard 和无人值守程序降级；后续兼容升级会在切换前备份完整 `current/`，失败时由用户运行安装根目录的一次性 `DicePP-Recover.cmd` 恢复旧程序、pre-upgrade 数据和 RuntimeUnit 原状态。

## Fixed

- 控制通道会等待 Manager 凭据准备完成后再建立连接，减少启动、升级和回退期间的无效重连与健康误判。
- 升级回退已将本地恢复结果与控制通道状态分开裁决；程序、配置和数据成功恢复时，暂时断开的控制通道只作为降级告警记录。
- 修复先攻列表改昵称后重掷可能产生重复条目，以及同值结果提示具有误导性的问题。

## Risk Notes

- 本 RC 包含 Manager 与配置应用行为变更，默认通过官方发行包手工迁移，不开放 Manager 自动安装。
- Windows 保留现有自包含目录时使用 Portable 覆盖解压；Setup 仅用于新的空目录，旧数据通过归档恢复。
- RC20 作为新的 Windows 手工迁移基线，不扫描、迁移、恢复或清理未正式发布版本遗留的 UpdateGuard 状态；旧遗留物不会阻止本版本启动。从源码运行时必须使用 Python 3.13，并重新创建旧版本虚拟环境。
- Linux 升级链路不会替换常驻 Manager；手工迁移时应同步更新完整标准部署，使 Manager、Bot 与 Dashboard 使用同一版本。
- 本版本不包含数据 schema、配置 schema、Compose service、volume 或 network 迁移。
