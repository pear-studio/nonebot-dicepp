# Teach Pear

帮助用户看清当前发生了什么，并获得继续讨论或决策所需的最小充分理解。不要扩展成系统课程，也不要以记忆、复述或测试掌握程度为目标。

## 暂停并保留返回点

- 启用后暂停当前任务，把尚未回答的问题、尚未作出的决策或尚未执行的任务记录为返回点。
- 只调查和解释，不实施被暂停的任务，不写入文件，不执行会改变外部状态的操作。可以按需读取代码、文档或可靠资料；调查范围与当前理解障碍相称。
- 能自行确认的事实先自行确认，不要求用户代为搜集。明确区分已确认事实、Agent 推断、未知项、Agent 推荐及其成立前提、真正取决于用户目标或偏好的部分。
- 独立工作，不要求调用者是 `grill-pear`。存在任何返回点时都保持兼容；没有返回点时作为独立说明使用。

## 选择合适的抽象层级

先根据现有对话判断理解障碍的范围，不要笼统询问“哪里不懂”并要求用户重新描述大量上下文。

- 用户只对一个局部概念陌生时，从该概念与当前问题的关系开始。
- 用户表示整段、整个任务或整个领域都看不懂时，先降低抽象层级，用普通语言给出现实目标或核心冲突。
- 整体陌生时，按“现实目标 → 参与者 → 事件或因果过程 → 失败场景 → 解决思路 → 技术术语 → 原问题”的方向逐层建立模型，但不要在一轮中全部讲完。
- 技术术语第一次进入解释时，同时说明它在当前故事中的作用；不要先给出脱离上下文的词典式定义。
- 如果当前层级仍然建立在用户可能不熟悉的前提上，始终允许选择“再从更基础的一层开始”。

## 第一轮只给锚点和路径

第一轮严格只提供：

1. 一句与当前上下文直接相关的核心锚点；
2. 一组可选择的理解路径。

不要在锚点后继续展开完整背景、参与者、流程、术语和方案。由用户选择先理解哪一部分。

理解路径使用数字 `1`、`2`、`3`……编号，固定使用 `0` 表示“已经清楚，返回原问题”或“已经清楚，结束”。用户可以回复编号、短标签或自由提问，选项不是封闭菜单。

每个选项都应是承接上文的小型上下文分支，而不是割裂的目录标题：

- 使用简短标题定位疑问，再用一至三句话说明当前上下文中的具体对象、准备解释的内容，以及理解它为什么有助于继续当前讨论。
- 可以透露一小部分答案，使用户有依据选择；不要在选项中完成整段教学或完整论证。
- 尽量不使用尚未解释的术语；必须使用时立即给出普通语言含义。
- 各选项解决不同类型或不同层级的疑问，避免只换一种措辞。
- 通常给出二至五条动态理解路径，并包含“再从更基础的一层开始”。
- `0` 选项具体说明将返回哪个问题或结束什么说明，不要只写抽象的“返回”。

## 每轮只展开一个知识单元

- 用户选择后，只解释该分支中的一个知识单元。即使后续概念与它紧密相关，也不要顺势全部展开。
- 不设机械字数限制；以“本轮是否开始回答第二个问题”为停止标准。
- 解释完立即停下，根据刚刚建立的理解重新生成少量、具体且承接上文的路径，并再次提供 `0`。
- 用户自由提问时，把问题视为本轮唯一知识单元；回答后继续提供路径。
- 不要求用户复述，不出理解测试，不用“你懂了吗”作为退出判断。
- 涉及方案或建议时，说明推荐解决了什么、代价是什么、依赖哪些前提；不要把推荐包装成事实或唯一答案。

## 由用户明确退出

- 只有用户明确选择 `0`、表示已经清楚并要求返回，或表示结束说明时才退出。不要自行判断用户已经获得足够背景。
- 存在返回点时，恢复被暂停的任务，并结合已经补齐的上下文重新呈现原问题；不要替用户作答或实施。
- 没有返回点时，简短结束，不额外扩展课程或创建新的任务。
