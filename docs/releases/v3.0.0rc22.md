# v3.0.0rc22

- 数据变更: no
- 配置变更: yes
- 变更范围: runtime, dashboard, manager, deployment, config, documentation
- 自动升级: yes
- 最低 Manager 版本: 1.0
- Linux Manager handoff 协议: 1

## Added

- Dashboard 新增查询数据库审查与一键修复：可以查看有效词条、重定向和逐项问题，按名称、英文、来源或内容搜索，并在执行前预览删除与行为变化。
- 查询数据库可以分别启用或停用；查询命令和 Persona 共用同一启停状态。修复会备份原数据库，再以规范结果替换当前数据库。

## Changed

- 内容管理和数据浏览改为左侧资源导航、右侧工作区布局；查询数据库列表可以独立收起，长数据使用固定高度详情展示，每页显示 25 条。
- 查询数据库运行格式收敛为名称、英文、来源和内容；分类、标签及旧筛选语法不再参与查询。重名词条按稳定顺序使用第一条，可能被隐藏或持续触发选择的冲突会在 Dashboard 中提示。
- 每次查询只使用当前选定的数据库；多个数据库仍可独立存放、启停和切换，不再通过群私设形成覆盖搜索链。
- 配置优先级调整为代码默认值、`config/user.json`、Bot 配置和环境变量。新安装包不再包含 `config/global.json`，遗留文件保留但不再读取或改写。

## Fixed

- 修复 Persona 午夜日报可能被整体超时取消，以及日终 SA 规划阻塞日报投递的问题；后台 LLM 请求使用独立超时，SA 规划改为日报后的单飞任务。
- 日报开场白不再复用并污染角色日常对话历史，两段日报的发送失败彼此隔离。

## Deprecated

- 停用 `.私设`、`.hb`、群私设 XLSX 导入和 `query_homebrew` 覆盖链路；既有磁盘数据不会被删除或迁移。

## Risk Notes

- 已采用 v3.0.0rc21 标准部署的实例可在 Dashboard 中由管理员确认后升级到本版本；Linux 使用 Manager handoff v1，Windows 失败时保留安装根目录的一次性 `DicePP-Recover.cmd`。
- 旧 `config/global.json` 不再生效。未修改过随包默认文件的标准实例无需迁移；若曾有意写入自定义设置，应将仍需保留的稀疏字段转写到 `config/user.json` 或对应 Bot 配置。源码部署若存在 tracked global 的本地改动，需先按 Git 提示处理后再更新源码。
- 一键修复查询数据库只在管理员明确操作后执行，并先展示影响；原数据库会改名保留为默认停用的备份。升级本身不会自动改写查询数据库或其他业务数据。
- 本版本不包含数据 schema、Compose service、volume、network 或 deployment schema 迁移。Final Candidate 必须通过与 rc21 真实发布字节绑定的 Windows/Linux 升级、恢复和回退矩阵后才能晋升。
