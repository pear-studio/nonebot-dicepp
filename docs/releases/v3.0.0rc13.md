# v3.0.0rc13

- 镜像: ghcr.io/pear-studio/nonebot-dicepp:v3.0.0rc13
- Windows: `DicePP-v3.0.0rc13-win64-Portable.zip`、独立 `DicePP-v3.0.0rc13-win64-Setup.exe` 和 Velopack feed
- 数据变更: no
- 配置变更: no
- 变更范围: manager, dashboard, documentation
- 自动升级: no
- 最低 Manager 版本: 1.0

## Fixed

- 修复 Windows 自动升级在安装确认阶段误拒合法的 Velopack assets feed（裸数组被误判为 invalid JSON），升级事务无法创建的问题。
- 修复 Windows 自动升级缺少当前版本回退材料导致的 preflight 拒绝：Portable 首次升级必然触发，Setup 第二次升级也会触发。Manager 现在会在缺失时从当前版本 Release 下载并校验回退材料，升级成功后自动维护该材料。
- 修复 Linux 自动升级健康检查恒定失败：Dashboard 与 Manager 的心跳时间戳格式不一致（epoch 秒 vs ISO-8601）。Dashboard 改写 ISO-8601，Manager 同时兼容旧 epoch 格式。
- 修复实际成功的回退被误报为回退失败，且 Manager 每次重启都重放整个回退（停 Bot、重建旧容器、重放旧归档）的问题。已判定失败的回退不再自动重放；在成功恢复归档或成功升级后，相关保护自动解除。

## Changed

- `/api/bots/status` 的 `last_heartbeat_ts` 字段 JSON 类型由 string 变为 number（epoch 秒，解析失败时为空字符串）。Dashboard 前端 `fmtRelativeTime` 经 `parseFloat` 兼容两种类型；按字符串处理该字段的外部脚本需要调整。

## Risk Notes

- 本版本包含 Manager 自身变更，按发布契约 `自动升级` 为 `no`：任何实例都不能经 Manager 自动安装本版本，需按下方路径手工迁移。
- v3.0.0rc11/rc12 实例的自动升级链路在出厂代码中已损坏（见上 Fixed），无法自动升级到本版本。手工迁移路径：
  - Windows：下载本版本 Portable 或 Setup，按 `docs/windows.md` 手工迁移；`config/`、`data/`、`content/` 等实例数据不受影响。
  - Linux：下载本版本 Linux 发布包，`docker load` 后 `DICEPP_IMAGE_TAG=v3.0.0rc13 docker compose up -d --pull never`（该路径已在 rc12 验收中实证）；Compose 文件如需变更必须整体替换，不可用 override 覆盖端口/卷。
- 迁移到本版本后，后续兼容版本的自动升级方可使用；本版本的升级链路修复将在下一版本的真实升级验收中端到端验证。
