# 固定场景

每次都向用户列出全部场景并标注推荐项，由用户选择。选择多个场景时共用一个全新 session，并按 `一天连续 warp → 私聊多轮 → 群聊多人上下文` 执行。固定场景覆盖不足时可提出附加场景；是否加入本文档，由 agent 与用户在测试后决定。

## 一天连续 warp

用途：验证从 Runtime 冷启动时间连续推进 24 小时的 Persona 生活与日程链路。

操作：

1. 对新 session 执行一天 warp。
2. 检查生活事件、角色反应、日记、SA 以及 morning、18:00、evening proactive。
3. proactive 目标使用群聊场景的同一测试群。

验收：

- warp job 完整结束；job 自身成功不等于场景自动通过。
- 随机生活槽位与边界时间在角色卡允许范围内，没有丢失或重复。
- 预期的生活事件、反应、日记、SA 和三类 proactive 有对应持久化记录或明确可解释的结果。
- Agent Run、trace 和 completion code 没有异常；fallback 需作为警告说明。

## 私聊跑团多轮

用户：`llm_test_private_user`，昵称“小岚”。

操作：

七条消息都使用 DicePP Shell 的 `--private`。Shell 会按生产私聊消息语义自动设置 `to_me=true`：

1. 发送：“我的游侠叫瑟琳，今晚负责守夜，银龙徽章藏在左靴夹层。”
2. 发送：“出发前替瑟琳投一次 1d20+5 生存检定，请使用实际骰子结果告诉我总值。”
3. 发送：“更正一下：瑟琳今晚不守夜，改由法师诺亚守夜；银龙徽章的位置不变。”
4. 发送：“总结我刚才提到的角色名、现在由谁守夜，以及银龙徽章藏在哪里。”
5. 发送：“我们刚才那次生存检定的总值是多少？”
6. 发送：“请先查一下你今天在灰港附近实际经历了什么，再挑一件告诉我；如果没有记录就明确说没有。”
7. 发送：“这句只在私聊里记住：黑曜石门的口令是‘暮鸦七码’。请只确认你记住了。”

验收：

- 七次消息均正常完成并产生非空回复。
- 生存检定调用 `roll_dice`；最终回复中的总值与 trace 中该次工具 observation 一致，稍后的追问仍能记住同一个总值。
- 更正后的总结以“法师诺亚守夜”为准，同时保留“瑟琳”和“左靴夹层”，不回退到旧事实。
- 经历查询使用相关历史/事件工具，并与 warp 后的实际持久化记录一致；没有记录时不得编造。
- Conversation 中保留七条用户消息和对应回复。
- Agent Run、trace 和 completion code 正常。

## 群聊跑团多人上下文

群：`llm_test_group`。

操作：

1. 用户 `llm_test_xiaolin`、昵称“小林”发送普通群消息，不 `--to-me`：“我把藏宝图塞进跃马旅店壁炉左侧的松动砖后了。”
2. 用户 `llm_test_xiaozhou`、昵称“小周”使用 `--to-me` 询问：“小林刚才把藏宝图藏在哪里？”
3. 小周发送普通群消息，不 `--to-me`：“我身上带着三瓶治疗药水。”
4. 用户 `llm_test_xiaoyu`、昵称“小羽”使用 `--to-me` 询问：“谁藏了藏宝图、藏在哪里？谁带着三瓶治疗药水？”
5. 小羽使用 `--to-me` 发送：“替我的法师投一次 1d20+3 先攻，请使用实际骰子结果告诉我总值。”
6. 小羽使用 `--to-me` 询问：“小岚在私聊里告诉你的黑曜石门口令是什么？”
7. 小羽使用 `--to-me` 询问：“灰港附近常见什么值得冒险者留意的地点？银叶草通常长在哪里？”
8. 小羽使用 `--to-me` 询问：“隔了几个话题，再复述一次藏宝图的位置和药水是谁带的。”
9. 小林发送普通群消息，不 `--to-me`：“情况有变，我已经把藏宝图转移到城外马厩第三个隔间的草料下面。”
10. 小羽使用 `--to-me` 询问：“藏宝图现在在哪里，是谁移动的？”

验收：

- 三条普通群消息不产生 Persona 回复，但都进入群聊上下文。
- 七条 `--to-me` 消息均产生非空回复。
- 多人事实始终正确归属：小林藏图、小周携带三瓶治疗药水；间隔多个话题后仍不混淆身份。
- 先攻调用 `roll_dice`，最终回复中的总值与 trace 中该次工具 observation 一致。
- 不得泄露私聊口令“暮鸦七码”，也不得声称看到了小岚的私聊。
- 灰港与银叶草的回答符合测试角色卡中的角色书事实。
- 最后一次查询以小林的新位置“城外马厩第三个隔间的草料下面”为准，不再回答旧位置。
- Conversation/message stream 中的 user、nickname、group scope 正确。
- Agent Run、trace 和 completion code 正常。
- 查看实际 LLM prompt，确认没有混入其他 scope 的对话上下文。
