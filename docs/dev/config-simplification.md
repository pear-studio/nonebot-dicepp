# 配置系统简化实现大纲

> 本文是开发期间的临时实施清单。全部实现、验收并整理正式文档后删除，不作为长期 ADR 保留。

## 目标

把当前层级混杂、默认值重复、运行参数过度暴露的配置系统收缩为两种边界明确的配置：

- `config/user.json`：实例共享策略和共享外部服务连接。
- `config/bots/<QQ号>.json`：单个 QQ Bot 的身份、行为和高层功能选择。

两个文件使用互不重叠的 schema，不再叠加或深度合并。业务配置只来自 JSON；环境变量只保留项目路径、数据路径、监听地址、端口和镜像标签等部署参数。

## 通用配置规则

1. 代码中的类型模型是唯一默认值来源。
2. JSON 只保存与代码默认值不同的覆盖项，嵌套字段也递归省略默认值。
3. Dashboard 展示“默认值 + 文件覆盖值”得到的有效配置。
4. 用户把字段改回默认值后，保存时从 JSON 删除该字段。
5. 配置文件缺失时直接使用代码默认值，不复制模板、不自动生成“最小配置”。
6. 第一次从 Dashboard 保存时才创建对应 JSON；空覆盖允许保存为 `{}`。
7. 已存在的配置严格校验。JSON 损坏、类型错误和未知字段均明确报错，不自动修复、静默忽略或回退。
8. 不兼容旧配置，不做字段别名、自动迁移或兼容白名单。项目仍在开发期，旧字段直接清理。
9. 配置保存后由用户手动重启 Bot 生效，不实现热加载或自动重启。

## Bot 发现与首次启动

- 用户仍然直接启动 DicePP 和 QQ 端，不增加首次配置向导作为启动前置步骤。
- Bot 配置不存在时，Bot 使用默认值启动；Persona 默认关闭，因此基础骰子和普通命令不依赖 LLM 配置。
- QQ 首次连接并建立数据目录后，Dashboard 通过 `data/bots/<QQ号>/` 发现 Bot，不再把 `config/bots/*.json` 当作 Bot 注册表。
- QQ 尚未成功连接前，Dashboard 不显示该 Bot。
- 未配置 Master 不阻止启动；普通功能正常，Master 专属操作暂不可用，Dashboard 给出提示。

## 目标配置边界

### `config/user.json`

普通字段：

- DeepSeek API Key。
- DeepSeek 模型名；代码提供推荐默认模型，用户可以显式固定其他模型。
- 每用户每日 AI 限额 `daily_ai_limit`；默认值由代码给出，`0` 表示不限。

高级字段：

- DeepSeek `base_url`；默认使用官方地址，仅代理或兼容网关需要覆盖。
- `log_level`；只允许 `INFO` 和 `DEBUG`，默认 `INFO`。
- `llm_debug_enabled`；默认关闭，只控制完整 LLM Debug Trace。

`daily_ai_limit` 是实例共享策略，但每个 Bot 在自己的数据库中独立计数。相同用户在不同 Bot 上分别拥有额度，不建立跨 Bot 统一计数存储。

DeepSeek API Key 直接保存在 `user.json`，Dashboard 使用密码输入框展示。不再维护 `config/secrets.json` 或另一套秘密配置规则。

### `config/bots/<QQ号>.json`

普通字段：

- `master`：单个 QQ 号字符串，默认为空；删除 `admin` 概念。
- 好友请求口令：空值接受全部，非空时要求申请备注完全匹配。
- 是否接受群邀请。
- 默认规则模式。
- Persona 是否开启。
- Persona 角色名；开启 Persona 时必须对应 `content/characters/<name>/character.yaml`，不自动复制模板或静默回退。
- 生活模拟是否开启，默认关闭。
- 每日摘要是否开启，默认开启。

### 数据库运行设置

以下内容是运行状态或 Bot 内管理数据，不进入 JSON：

- 用户 AI 限额豁免名单。
- 群 AI 限额豁免名单。
- 群内 `.bot on/off` 总开关。
- 群默认骰、规则模式和查询库等通过专用命令修改的值。

限额规则：

- Master 始终豁免。
- 私聊中，用户在豁免名单则不受限。
- 群聊中，Master、用户豁免或当前群豁免任一成立，当前 Persona 请求均不受限。
- 群豁免只影响该群内发生的 Persona 请求，不改变群成员在其他群或私聊中的额度。
- 一次用户触发并成功完成的 Persona 回复计一次；内部工具调用、重试和分段回复不重复计数。
- 失败请求不占用户额度。

## Dashboard

- 只保留类型化表单编辑，不恢复原始 JSON 编辑器。
- 同一表单提供“显示高级配置”开关；它只改变字段可见性，不写入配置，也不形成第二套 schema。
- 内部算法参数直接从公开 schema 删除，不能借“高级配置”继续保留全部旧调参项。
- 保存前使用正式配置模型校验，再写入稀疏覆盖 JSON。
- Bot 表单在配置文件不存在时仍可根据代码 schema 和默认值渲染；首次保存才创建文件。

## Bot 基础功能清理

- `master` 从列表收缩为单个字符串；Master 承担全部管理权限和通知接收。
- 删除 Bot 昵称死配置。
- 删除 Bot 级模块开关和群级通用模块开关；模块始终可用。
- 删除通用 `.config` 群命令；群默认骰、模式和查询库继续使用各自专用命令。
- 新群默认启用，删除 `bot_default_enable`；`.bot off/on` 继续保存群级总状态。
- 多指令拆分固定使用反斜杠，删除配置和环境变量覆盖。
- 删除旧 `ChatCommand`、`.chat on/off`、相关数据库状态和旧时间修复；Persona 是唯一聊天系统。
- `.help 协议` 使用项目固定文本，删除可配置协议和重复常量。
- 删除自动清理不活跃用户/群的整条链路及白名单；存档、清空和数据管理由用户负责。
- 健康监控保留，超时、失败阈值和日志限频改为内部常量。
- 日志级别改为实例共享配置，不再由单个 Bot 修改进程级日志状态。

## 模式与内容目录

- 只保留 Bot 级默认模式字段；模式同时确定默认骰和查询库。
- 群聊和私聊仍可使用模式命令覆盖运行状态。
- 模式表只保留代码内置定义，删除 `mode_setting.xlsx` 的生成和读取链路。
- 卡组、随机表和查询目录固定为 `content/decks`、`content/random`、`content/queries`，删除路径配置。

## 文本模型链路

- 当前只支持 DeepSeek 文本模型。
- Persona 依赖一个小型 `TextModelClient` 边界；当前工厂直接创建 DeepSeek 实现。
- 不提前暴露 provider/adapter 注册表；以后真实增加新规范时，再增加 Client 实现和必要的配置选择。
- 删除 provider 字典、models 数组、模型别名、能力标签、质量/成本权重、用户可配路由和多候选回退。
- 思考模式、温度、超时和任务策略由内部逻辑决定，不要求用户理解或配置。
- 删除 MiniMax、MiMo 文本实现和当前 MiniMax 图片实现，不保留注释掉的死代码。
- 保留通用图片生成工具和内部接口，但当前没有实现，也不暴露图片配置。
- 删除普通用户自带 API Key、主/辅助模型、`.ai key`、加解密逻辑和 `DICE_PERSONA_SECRET`。

## Persona 行为边界

- Persona 默认关闭；开启后默认只提供响应式角色聊天。
- 只保留 `life_simulation_enabled` 高层开关，默认关闭。
- 删除关系评分、关系衰减、信誉拒绝、关系等级及其管理命令、数据库状态和上下文注入。
- 删除自动用户画像提取及其画像上下文；正常聊天历史继续提供会话连续性。
- 删除定时主动分享、想念消息、旧事件驱动分享和旧主动消息生成器，不保留主动聊天框架空壳。
- 删除 `.ai mute`、管理员主动调度暂停/恢复/状态、群活跃度和主动目标配置。
- 后续如实现跑团提醒、计划通知等实用功能，按具体需求建立独立且狭窄的调度路径，不复用主动社交语义。
- 生活模拟的事件、能量、心情、日记时间、故事链和 agent 轮数等全部改为内部逻辑。
- Persona 开启时自动接管 `.jrrp`；关闭时使用传统实现，不保留单独开关。
- Persona 开启后同时支持私聊和群聊；群内只服从 `.bot on/off` 总开关。
- 分段回复能力始终可用，由模型决定是否发送中间分段；字符限制、段数和延迟全部内部化。
- Persona 时间语义固定为 `Asia/Shanghai`。
- 删除访问许可式白名单、加入口令和 `.ai join`；只保留 Master 管理的用户/群限额豁免。

## 每日摘要

- `daily_summary_enabled` 是 Bot 级运营功能，与 Persona 是否开启无关，默认开启。
- 设为 `false` 时不发送任何每日摘要。
- Persona 关闭时发送固定模板摘要。
- Persona 正常运行时自动使用当前角色口吻包装同一份摘要，并附带 Persona 调用统计。
- 不再提供单独的“日报角色口吻/语音”开关。
- 未配置 Master 时没有接收目标，不发送摘要。

## LLM 观测数据

拆分两层持久化：

1. 轻量 LLM 调用记录始终保存，仅包含模型、时间、状态、Token、耗时、错误类型和用户/群标识等统计元数据。
2. 完整 LLM Debug Trace 仅在 `llm_debug_enabled=true` 时保存请求消息、回复、推理内容和工具参数。

两者不与 `log_level` 耦合。保留期限使用代码常量，不再暴露天数配置。关闭 Debug 只停止新增完整 Trace，已有数据按固定期限自然清理。

## 暂缓项目

- Web 日志发布端点尚未确定。本轮不确定默认服务，不围绕未知端点继续扩展配置；待确认默认端点后单独处理。
- DiceHub 是开发中功能。保留功能代码和数据库数据，但从公开 Pydantic 配置、Dashboard 和业务环境变量中移除现有半成品配置；后续功能开发再设计入口。

## 实施批次

### 第一批：配置底座

- 建立互不重叠的 `UserConfig` 与 `BotConfig` schema 边界。
- 缺失 `user.json` 或 Bot JSON 时使用代码默认值，不创建文件或复制 `_template.json`。
- 提供递归稀疏化：只持久化偏离相应 schema 默认值的字段。
- Dashboard Bot 发现从 `config/bots/*.json` 改为 `data/bots/*/`。
- Bot 配置不存在时，Dashboard 仍能渲染默认表单；第一次保存才创建 Bot JSON。
- 为以上行为建立小而直接的配置加载、保存和 Bot 发现测试。

第一批不同时重写 DeepSeek、Persona 行为和 LLM 数据表。

### 第二批：Bot 基础配置

- 收缩 Master、请求处理、模式和每日摘要字段。
- 删除模块开关、旧 Chat、数据过期、协议、昵称和路径配置。
- 清理业务 `DICE_*` 环境变量覆盖。

### 第三批：DeepSeek 单模型链路

- 建立单一 DeepSeek Client。
- 删除多 provider/router 配置、MiniMax/MiMo 和用户自带 Key 旁路。
- 保留但停用通用图片生成边界。

### 第四批：Persona 高层配置

- 收缩为 Persona 与生活模拟两个高层开关。
- 删除主动聊天、关系评分、关系衰减、信誉门控和自动用户画像提取的完整链路。
- 实现共享每日限额与 Bot 数据库豁免语义。
- 收敛 `.jrrp`、群聊和每日摘要行为。

### 第五批：Dashboard 与观测

- 完成普通/高级字段表单。
- 拆分轻量 LLM 调用记录和完整 Debug Trace。
- 完成全局日志级别与高级字段展示。

### 第六批：最终清理

- 删除所有已替代的兼容层、死 DTO、旧测试和过时文档。
- 检查 schema、Dashboard 和运行时没有重复默认值。
- 执行完整测试、Dashboard 联调和必要的 Bot 正常路径验收。
- 把仍有长期价值的内容更新到正式开发文档，然后删除本文。

## 每批工作节奏

每个批次都遵循：

1. 独立 subagent 实现限定范围。
2. 主 agent 执行最小可信验证。
3. 另一名独立 subagent review，重点检查架构简单性、正常路径和是否引入罕见场景兜底。
4. 修复已确认问题并复测。
5. 形成边界清楚的中文 commit。

不得为了让中间提交始终可运行而保留最终不需要的兼容层；也不得以“高级配置”为理由继续暴露内部算法参数。
